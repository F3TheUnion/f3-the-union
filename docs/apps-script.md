# Google Apps Script (`.googleAppsScript`)

A local mirror of the Apps Script project bound to the F3 The Union Google Sheet. It is a
**reference copy** — the source of truth is the Apps Script editor in Google. Nothing in the
Pages app imports it. Keep it in sync by hand after editing in the Apps Script IDE.

It was assembled by pasting half a dozen separate `.gs` files together, on purpose — keep it as
one file.

## What it does

Four jobs, all driven by time-based triggers in the Apps Script editor:

1. **BigQuery → Sheet → GitHub.** Queries `f3data.*` in BigQuery, writes results to sheet tabs,
   then commits the derived JSON back to this repo (`data/*.json`) via the GitHub API. This is
   what produces the "generated by a Google Apps Script" data files described in `CLAUDE.md`.
2. **KoG scoring.** Rebuilds King of the Gym scores from event facts and commits
   `data/team_*.json`, `data/pax_*.json`, `data/meta.json`.
3. **Slack charts.** Uploads Sheet charts as images into Slack channels.
4. **Open Q slot notifications.** DMs each site Q the unclaimed Q slots at the AO(s) they run,
   falling back to posting in the AO channel if the site Q can't be reached.

## Configuration

### Secrets — Script Properties, not the file

Read via `PropertiesService.getScriptProperties()`:

| Property | Used for |
| --- | --- |
| `slackBotToken` | All Slack Web API calls (`users.list`, `conversations.open`, `chat.postMessage`, file uploads) |
| `KOG_WEBHOOK_URL` | The dormant KoG standings post |
| `GITHUB_TOKEN` | `ghRequest_` — committing generated JSON to `abereanone/f3-the-union` |

### Constants

- `DEBUG_ON` — when `true`, `getTargetChannel_()` reroutes **channel** posts to
  `SLACK_CHANNEL_DEBUGGING`. It does not affect DMs.
- `SLACK_CHANNEL_*` — one const per Slack channel ID, defined at the top of the file.
- `GITHUB_REPO`, `KOG_DATA_BRANCH`, `NEVER_Q_DATA_BRANCH` — commit targets.
- `KOG_START_DATE` / `KOG_END_DATE` / `KOG_SCORE_ADJUSTMENTS` — the scoring window and manual
  point adjustments (M convo bonuses, kotters, out-of-town AO credit).
- `BQ_PROJECT_ID = 'f3data'` — the BigQuery billing project.

### The two AO tables

There are **two** separate AO lists with **different key formats**. This matters for any change
that crosses between them:

| List | Key format | Purpose |
| --- | --- | --- |
| `AO_SITEQ` (~line 69) | slug — `the_fountain` | Maps AO → site Q's F3 name (e.g. `Puppy mill`) |
| `AO_CONFIG` (~line 92) | display name — `The Fountain` | Maps AO → channel ID, enabled flag, `weeksAhead` |

They cover the same 13 AOs and now sit adjacent at the top of the file, so a change to one is
hard to make without seeing the other. `AO_SITEQ` is keyed by slug, `AO_CONFIG` by display
name — `aoSlug_()` joins them. Note `Peach` is site Q for **two** AOs
(`the_breakroom` and `the_clocktower`).

## Function map

### Slack user lookup + DM
- `getSlackUserId(username)` — normalized name → Slack user ID, memoized in Script Properties
  under `slackUserId_<normalized>`. Falls back to `users.list` on a miss.
- `normalizeName(name)` — lowercase, strip all whitespace.
- `lookupSlackUserIdFromApi(name)` — scans `users.list`, matching `display_name`, `real_name`,
  or `name`. **Throws** `Slack user not found: <name>` on a miss.
- `sendSlackDMByUsername_(username, text)` — `conversations.open` then `chat.postMessage`.
  Throws if either call comes back `ok: false`, which is what lets the open-Q-slot channel
  fallback trigger.
- `getAoToSiteQMap()` — `AO_SITEQ` array → `{ slug: siteQName }` object.

Cache caveat: user IDs are cached **forever**. If someone changes their Slack display name, the
stale entry keeps resolving. Clear `slackUserId_*` from Script Properties to force a re-lookup.

### GitHub
- `ghRequest_(url, method, payload)` — authenticated GitHub API call.
- `sheetToJSON(sheetName)` — sheet tab → array of row objects keyed by header.
- `commitFilesToGitHubSingleCommit(branch, message, files)` — blobs → tree → commit → ref move,
  so a multi-file update lands as **one** commit. `files` is `{ path: data }`; each value is
  `JSON.stringify`'d, so this only commits JSON.

### BigQuery
- `runBigQuery(sql)` → `{ headers, rows }`.
- `rowsToObjects`, `toDateKey`, `normalizeSheetDate`, `writeToSheet` — result shaping.
- `doAllMetrics()` — the umbrella metrics run.
- `getPaxMetricsBQ`, `getRZMetricsBQ`, `getAOAvgAttendanceBQ`, `getBDAttendanceBQ`,
  `getUniquePaxCountBQ` — individual metric queries.
- `getQReportRollingBQJsonToGitHub()` — powers `q/index.html`.
- `exportNeverQDataToGitHub()` — powers `never-q/index.html`.

### KoG
- `nightlyKoGRun()` — the trigger entry point: load metrics → `regenScores()` → Slack update.
- `regenScores()` — `buildFactPaxEvents` → `applyWeeklyCaps` → `generatePaxWeeklyScores` →
  `generateTeamScores`, then one commit of all KoG JSON.
- `buildKoGScoringGrid`, `validateKogHeaders`, `buildKoGMeta`, `addMissingPaxToWeeklyScores`,
  `isOutsideKog`, `fmtWeek` — supporting pieces.
- `sendKoGSlackUpdate()` — posts the standings to Slack.

### Charts
- `sendAllTheCharts()` — sends the full set.
- `getChartByTitle_(title)` — finds an embedded chart on the `Charts` sheet by title.
- `uploadChartBlobToSlack_(blob, title, channelId)` — Slack external upload flow.
- `getTargetChannel_(id)` — the `DEBUG_ON` router.
- `senduniquePAXPerWeek`, `sendAveragePAXPerAOChart`, `sendBeatdownChartToSlack`,
  `sendRedZoneChartToSlack` — per-chart wrappers.

### Open Q slots
- `postOpenQSlotsToSiteQs()` — the real entry point; see below.
- `postOpenQSlotsToAOChannels()` — thin wrapper kept **only** so the existing time-based
  trigger (bound to this name) keeps firing. Delegates to `postOpenQSlotsToSiteQs()`.
- `aoSlug_(aoName)` — `'The Fountain'` → `'the_fountain'`, the join between `AO_CONFIG`
  display names and `AO_SITEQ` slugs.
- `buildSiteQMessage_(entries)` — the DM body; one section per AO when a site Q covers several.
- `postEntryToChannel_(entry)` — the original channel post, now the fallback path.
- `sendSiteQDM_(siteQName, text)` — DM wrapper that honors `DEBUG_ON`.
- `postMessageToSlack_(channelId, text)` — `chat.postMessage`, throws on `ok: false`.
- `getCutoffDate_(weeks)` — today + N weeks as `yyyy-MM-dd`.
- `formatQDate_(dateStr)` — `2026-09-14` → `Mon, Sep 14`.

## Open Q slots flow

Notifications go to the **site Q by DM**, not to the AO channel. Channel posting still exists
as a fallback.

`postOpenQSlotsToSiteQs()`:

1. Filters `AO_CONFIG` to `enabled` entries.
2. Takes `max(weeksAhead)` across them so a **single** BigQuery query covers every AO.
3. Queries `f3data.analytics.future_event_info` for region `38363` where
   `planned_q_user_id IS NULL` and `start_date` falls between today and the max window.
4. Groups the resulting dates by `ao_name`.
5. Per AO: trims to that AO's own `weeksAhead` cutoff (which may be shorter than the query
   window) and skips it if nothing is left.
6. Buckets each remaining AO under its site Q via `aoSlug_` + `getAoToSiteQMap()`, so a site Q
   covering several AOs gets **one** DM rather than one per AO.
7. DMs each site Q.

The BigQuery `start_date` values come back as `'YYYY-MM-DD'` strings, which is why the cutoff
comparison is a plain string compare.

### Fallbacks

The slots still get seen if the DM can't be delivered:

- **Site Q not resolvable in Slack, or the DM is rejected** (renamed, typo, left the
  workspace, bot can't DM them) — `sendSiteQDM_` throws, and every AO in that site Q's bucket is posted to its own AO channel instead, using
  the original message wording. Logged with the site Q name and the underlying error.
- **AO missing from `AO_SITEQ`** — posted to its AO channel, logged as
  `no site Q in AO_SITEQ, falling back to channel`.

Because a site Q's whole bucket shares one lookup, a failure for Peach falls back for both
The Breakroom and The Clocktower together.

### Debugging

`DEBUG_ON = true` routes **both** paths to `SLACK_CHANNEL_DEBUGGING`: channel posts through
`getTargetChannel_`, and DMs through `sendSiteQDM_`, which prefixes the body with
`_(DM intended for <site Q>)_` so you can see who would have received it. Turn it on before
testing — otherwise a run DMs 12 real people.

### Changing who gets notified

- **Site Q changed at an AO** → edit that AO's row in `AO_SITEQ`. The name must match the
  person's Slack display name, real name, or username (compared with whitespace stripped and
  lowercased). If they were previously looked up under a different name, clear the stale
  `slackUserId_*` Script Property.
- **Add / remove / pause an AO** → edit `AO_CONFIG` (`enabled`, `weeksAhead`). Keep the display
  name in sync with `AO_SITEQ`'s slug — `aoSlug_` is the only thing joining them.

## Known warts

- **Loose globals.** `KOG_START_DATE` is assigned without `const`/`let`. `slackToken`, `userId`,
  `kinevil`, `floppy`, `uniball` are test leftovers at the top level.
- **Hardcoded webhook.** See the note under Secrets.
- **Throw-on-miss.** `lookupSlackUserIdFromApi` throws rather than returning null, so an unknown
  name aborts whatever loop it is inside. Wrap in try/catch when iterating.
- **`DEBUG_ON` only covers channels.** Any DM-based notification needs its own debug path.
